# ClickHouse migrations (plan 7.6)

`NNNN_description.sql` files, applied in order by `etl ch-migrate` and recorded in a
`ch_migrations(version, applied_at)` table. One file set for sandbox and prod: the database
and the cluster come from the settings (`CLICKHOUSE__DATABASE`, `CLICKHOUSE__CLUSTER`), never
from the file. Tables stay unqualified (`scripts/check_rules.py` refuses `clevrr_db.`).

- `0001_baseline.sql`: the sandbox schema (generated by `scripts/ch_baseline.py`).
- `0002_order_mv_replicated.sql`: `order_mv` replicated and sharded by the order (legacy's replicas disagreed and re-synced orders doubled). The shard table stays as `order_mv_shard_legacy` and its rows are copied in from every replica; the Distributed table is dropped and recreated, because a renamed Distributed table keeps reading the shard table's *name* (it would read the new, empty one).
- `0003_order_sharding.sql`: `order_click_attribution` sharded by the order, the same way. Statements marked `-- cluster only` are skipped on a single server.
- Applied to the sandbox's `clevrr_db` on 2026-10-19 (the TL's decision: v2 writes the sandbox's own tables). Drop the `*_shard_legacy` tables once the copy is verified.
